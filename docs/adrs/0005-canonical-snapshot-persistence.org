* Context and Problem Statement

Assurance snapshots need replayable persistence without turning serialized JSON
or a database row into semantic or authority state.

* Decision Outcome

Persist a canonical JSON projection identified by the vocabulary-manifest
revision and the snapshot digest.  Scheme POO values and pure validation remain
the semantic owner.  Loading a projection reconstructs candidate values, checks
the schema revision, recomputes the digest and reruns admission; deserialization
alone never restores support, Decision authority or Effect permission.

Unknown fields, missing required bindings, unsupported manifest revisions and
digest mismatches fail closed.  Storage engines may index projections but may
not mutate their meaning.

* Consequences

- Good: snapshots are portable and independently digestible.
- Good: persistence remains replaceable and non-authoritative.
- Bad: schema evolution requires explicit projection migrations and replay.

* Confirmation

- Permuting input objects produces identical canonical bytes and digest.
- Presentation-only mutation cannot enter an admitted snapshot.
- A stale or unsupported persisted projection is rejected before planning.
