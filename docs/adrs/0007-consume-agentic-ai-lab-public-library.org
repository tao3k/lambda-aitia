* Context and Problem Statement

Lambda Aitia is a Software/SDLC contribution built on Agentic AI Lab.  Agentic AI Lab is
not an optional adapter from which Aitia should minimize imports; it is the
project's public mechanism and library dependency.  Graph traversal, impact
trajectories, POO composition, functional flow, source locks, Standards,
module loading, verification handoff and generic Runtime mechanisms belong in
Agentic AI Lab so every contribution can reuse them.

The former exact-owner allowlist confused auditable ownership with minimizing
the dependency surface.  It also encouraged Aitia to reason about individual
Agentic AI Lab source paths instead of the public library contract Agentic AI Lab releases.

* Decision Drivers

- Reuse Agentic AI Lab's complete public mechanism library where Aitia needs it.
- Keep generic mechanisms and high-quality algorithms in Agentic AI Lab rather than
  duplicating them in Aitia.
- Keep Software/SDLC semantics, assurance policy and the production Python SDLC
  Runtime in Aitia.
- Preserve the one-way dependency: Agentic AI Lab never imports Aitia.
- Make public-library compatibility and clean installation executable release
  gates.

* Considered Options

1. Keep an exact and intentionally small Agentic AI Lab owner allowlist.
2. Copy required mechanisms into Aitia to reduce parent dependencies.
3. Treat Agentic AI Lab as Aitia's public mechanism library and govern the ownership
   direction plus public API stability.

* Decision Outcome

Choose option 3.  Lambda Aitia may consume any reviewed public Agentic AI Lab library
needed by its implementation.  There is no architectural target to minimize
that dependency.  Agentic AI Lab owns and publishes reusable mechanisms, including
Graph/Impact Graph algorithms and trajectories, POO CLOS, functional flow,
Sources Lock, Standards, User Interface discovery, verification adapters and
generic Runtime/lifecycle infrastructure.

Lambda Aitia owns Software/SDLC concepts, NASA software-engineering knowledge,
ADR/RFC integration, assurance semantics, Aitia ABI projection and its
production Python SDLC Runtime.  It does not fork or locally reproduce a POO
Flow mechanism merely to avoid a dependency.

Direct internal =:agentic-ai-lab/src/= paths remain migration debt.  Agentic AI Lab should
publish cohesive Library facades; Aitia should consume those facades as they
become available.  This is API stabilization, not dependency minimization.

* Consequences

- Good: shared mechanisms and optimized algorithms retain one Agentic AI Lab owner.
- Good: Aitia can use the complete Agentic AI Lab feature set needed by production
  Software/SDLC flows.
- Good: review focuses on semantic ownership and public API stability.
- Neutral: a Agentic AI Lab release becomes an explicit Aitia build dependency.
- Bad: incompatible Agentic AI Lab public-library changes block Aitia until the two
  repositories are advanced together.

* Confirmation

- A clean Agentic AI Lab installation exposes every public library imported by the
  pinned Aitia revision.
- Aitia production build, Scheme tests, native ABI and Python tests run against
  that installation without dirty parent sources.
- Agentic AI Lab source and import-policy checks continue to reject Aitia imports.
- Graph, Sources Lock, Standards and Runtime mechanisms have no duplicate Aitia
  implementation.
