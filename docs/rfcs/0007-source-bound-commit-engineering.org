#+title: RFC 0007 — Source-bound commit engineering

* Engineering identity and readable intent
:PROPERTIES:
:ID: lambda-aitia-commit-engineering
:ENGINEERING_ID: RFC-0007
:STATUS: implementation-in-progress
:END:

This RFC owns the engineering item for source-bound commit narration. Its
identity is independent of PR 2 and of NASA requirements such as SWE-083 and
SWE-084. The RFC number identifies this design record; it is not a fabricated
issue number or a claim of NASA certification.

** Ownership

The NASA Profile selects applicable engineering obligations and their evidence
methods. It does not prescribe a Conventional Commit grammar. The project
Scheme/POO configuration owns its title convention, vocabulary, scope mapping
and references to engineering records. Project language sources supply context
for Agent deliberation; an optional =primaryLanguage= is an explicit project
declaration, not a global default. JSON supplies ordinary configured values
through the same Scheme Contract. The program selection is
=programs.jj.enable= and =programs.jj.settings=, separate from runtime services.

Rust reads the current JJ cut, changed paths and configured source documents
through JJ's Rust library and backend. Agent narration cannot replace those
observations. Scheme verifies the ORG Element and executes its uniqueness
Contract before admitting a configured engineering reference. ASCENT derives
eligible candidates and explicit missing, conflicting or out-of-scope relations.
The LLM proposes intent and explains its choice; eligibility does not authorize
a write or establish that the proposed intent is factually correct.

** RFC, ADR and domain relations

The current project configuration declares one engineering reference,
=RFC-0007=, and one commit scope, =gitops=. The ADR module already owns
decision status, revision, options, consequences and typed links including
=refines-rfc=, =implements-rfc= and reciprocal supersession.
[[file:../adrs/0002-standardize-ADR-and-connect-RFC.org][ADR 0002]] defines
the RFC relationship and the Assurance projection.

The review graph should keep the engineering item, the applicable
architecture decisions and the affected domains as distinct relations.
A change may have one primary engineering reference for its title and
several related decisions. A domain groups responsibilities declared by
the project and its Modules. A commit scope identifies affected paths.
Domain membership should follow declared Module ownership and typed
document links. The proposal can suggest additional relations for review.
It cannot establish them by matching a filename or title.

Read the referenced ORG Elements at the selected JJ revision. Use the ADR
module to validate decision status, revision and links. ASCENT can then
relate changed paths to their declared domains, RFCs and relevant ADRs.
A superseded decision remains visible in historical review and needs
reassessment before it can support a current claim. The existing ADR
Assurance projection preserves this distinction and grants no authority.

[[file:../adrs/0009-rust-engineering-runtime-and-DE-library.org][ADR 0009]]
and [[file:0006-engineering-runtime-and-library-boundaries.org][RFC 0006]]
provide a recorded pair for the execution-runtime domain. The current
commit engineering Case keeps RFC 0007 as its primary reference. Related
decisions should appear when an explicit relation has been admitted.
The ADR and domain projection into commit review and GQL remains open.

** Structured proposal

An Agent supplies =identity=, =reference=, =type=, =scope=, =summary= and
=rationale=, alongside the reviewed body, ORG assessment and current context.
The proposal also records =language= and =languageSource=. The LLM assesses
the project documentation and any explicit primary-language declaration.
ASCENT relates the proposed language to an observed project source and reports
conflicts with an explicit project declaration. There is no built-in English
requirement. Unicode narration is valid; structural checks reject control
characters, not languages. Neither a source link nor a character check proves
that a text is written in the proposed language. Linguistic and substantive
correctness remain review obligations. A rationale is retained as proposed reasoning, not execution
evidence.

Without an explicit primary-language declaration, the Agent may infer the
language from the observed main project documents; it does not fall back to
English. A missing or stale language source leaves the proposal Open. An
explicit declaration that conflicts with the proposal also leaves it Open;
ASCENT exposes that conflict for review rather than choosing a language by
character set or filename.

The linked push fixture uses this project's English review style and reads a
recorded ORG engineering item. A proposal conflicting with its language
declaration and a proposal citing an unrecorded language source each leave a
distinct Open reason without issuing a prepare attempt. The renderer does not
select a project language; its Evidence and Open labels are section names.

For this RFC the project policy can render:

#+begin_example
AITIA-RFC-0007 feat(gitops): Validate source-bound commit intent
#+end_example

The reference must match the configured document, unique stable ORG ID and
=ENGINEERING_ID= on the same headline. PR identity is a review association.
NASA SWE identifiers name obligations. Neither supplies a missing engineering
item. Other projects may declare their own engineering records and vocabulary;
the runtime must not derive an identifier from title keywords or manufacture a
counter.

The configuration export selects the NASA policy once. Its Rust caller
keeps the Scheme review configuration rooted while it gathers JJ and
provider facts. The review consumes that object with the captured facts.
Rust uses the public configuration projection to select its checks, and
each subsequent admission resolves the configuration for its own cut.

The Scheme policy evaluates each immutable review observation with the
ASCENT one-shot evaluator. Each invocation checks that the evaluation
finished before using its rows. Preparation and subsequent admission
capture fresh facts through the same policy. Historical evidence remains
available through its revision and recorded source.

ASCENT compares the declared =(identity, document, Element)= relations
separately from the ORG observations that resolve them. Two distinct
document/Element pairs for one identity are a conflict even if one document
is missing, belongs to an old cut, or does not contain the claimed Element.
An unverified declaration remains visible as unresolved alongside the
conflict. The proposal stays Open and cannot prepare a write. Identical
declarations do not create a second origin. Multiple source observations for
the same path cannot establish its current identity by selecting the one
that passes validation.

of the same path failed validation. The fixed rules reject both. The suite
also covers a retired origin, a forged Element, conflicting Element IDs in

=aitia jj commit= now reports =recordedReviewBookmarks=. JJ reads them from
the current operation, without snapshotting, fetching, or reading a provider.
JJ uses its index to find recorded remote bookmark targets reachable from
the candidate. For each remote it keeps targets that are not ancestors of
another reachable target on that remote. It retains distinct bookmarks at
the same head, incomparable targets after a merge, and reachable conflicts.
A conflicted target has no selected commit. JJ excludes its local Git
pseudo-remote and resolves the push lease under the operation lock.
An empty discovery result does not establish PR absence.
The list is discovery input, not admitted provider evidence or a reviewed
push destination.

The same discovery result reports a canonical =githubRepository= when the
current JJ backend resolves every configured fetch and push URL to the same
repository on =github.com=. An HTTPS or SSH URL contributes only its
=owner/repository= identity. Alternate hosts, split destinations, and local
remotes leave that field empty. Git configuration can change without
advancing the JJ operation, so this observation must be re-read before
provider association; it cannot be replayed as an immutable operation fact.

The read-only =aitia jj commit= context also emits =providerReview= for a
single unambiguous GitHub bookmark. Rust queries GitHub through the
recorded JJ remote. A PR response must name the same repository for both
head and base, match the source bookmark, and identify the exact recorded
head. Each check run must bind that head. A partial, unavailable or
inconsistent check-run list is unknown. Local and unsupported remotes do
not make a request. The runtime re-observes the bookmark and configuration
before returning the provider result. GitHub redirects are not followed.

The Project manifest does not declare PR number, source or target branch.
ASCENT relates the provider response to the exact JJ bookmark and an
eligible recorded head. When a GitHub bookmark is relevant and the
association is ambiguous, stale, or unavailable, =gitops.pull-request=
remains Open. An empty open PR list triggers a [[https://docs.github.com/en/rest/git/refs#get-a-reference][GitHub Git reference lookup]].
The exact branch ref must identify a commit at the recorded JJ head before
ASCENT derives the no-open-PR route. Missing refs, unexpected object types,
and moved heads cannot close the obligation. The list and ref are separate
provider reads. Prepare, apply and push repeat them as needed, and JJ still
enforces the remote lease at transport.
The provider query requires a canonical GitHub remote and a unique
bookmark candidate. Split destinations and ambiguous candidates cannot
establish PR absence.

The review context binds the repository, remote, PR number, source,
source revision, target branch, target revision and provider update time.
Prepare, apply and push observe the association again. A change to the
reported target revision requires a new review even when the target branch,
source revision and provider update time are identical. A response missing
the target revision cannot establish a PR association. Under the JJ
operation lock, push resolves the selected
remote and reads the selected bookmark's lease before transport. A GitHub
destination must match the repository, remote, bookmark and head from the
current PR association or from a successful observation that found no open PR.
Once JJ has selected the lease, the Runtime reads the provider and its
checks again. The fresh observation must equal the facts admitted by Scheme. A retarget, target revision change, replacement PR, lost provider,
or transition between a PR and confirmed absence refuses transport even when
the remote Git head is identical. A split or undiscovered GitHub route is
refused. Review binds an opaque identity of the ordered effective fetch
and push URLs. Under the lease, the selected remote, bookmark, head and
route identity must match a reviewed observation. This also applies to
local remotes, which require no provider request. GitHub PR
metadata remains external to JJ's lock and can change after the final read.
After the admission callback returns, the Runtime reopens Git configuration
and compares the ordered effective fetch and push URLs with the route used
for admission. A missing route or changed URL refuses transport before a
JJ transaction starts, including when both destinations have the same
bookmark head. JJ retains ownership of the bookmark lease and Git transport.
Git resolves the remote name when its transport starts, so an external
configuration write after the final read remains outside this check.
Recovery reads the existing operation outcome and issues no new effect.
The provider's update time is not a monotonic event sequence.

After losing a push response, =aitia jj git push --recover --bookmark NAME=
accepts the original =attempt= envelope and an optional =--remote=. A
successful transport must positively acknowledge the single requested
bookmark, and JJ's transaction must record the applied commit as its remote
target. AITIA then records the remote name and bookmark on the visible JJ
operation. Recovery checks that operation's exact applied parent and the
recorded remote target before returning the historical acknowledgement.
It uses local JJ history without contacting the remote. If transport
finished but its acknowledgement never became visible in JJ history, the
outcome stays unresolved. A historical acknowledgement carries no claim
about the current remote branch and grants no further write.

** Commit description layout

The previous renderer joined the title and a free-form body. The ORG
Contract checks the evidence claims in separate review material; it does not
by itself require those claims to be presented in the commit. A valid preview
could therefore omit evidence prose, unresolved work, or both.

The description now renders structured narration against the applicable
commit-check results from ASCENT. Scheme seals the rendered
text together with the reviewed claims. The Agent supplies concise prose
in the project's language and references the applicable relation rows. The
renderer owns section order, blank lines and list formatting. Plain Git
output must stay readable without a Markdown renderer. The section roles are:

- Change and rationale: what changed and why a reviewer should care.
- Evidence: the checks actually run, their observed result and scope. A
  claim of passing must refer to admitted evidence. An absent check cannot
  be written as a pass. OpenSysML reports the parsed file or the number of
  parsed files here when the full affected model scope was verified.
  An unresolved applicable model check appears in Open.
- Open: unresolved obligations that apply to this change or its verified PR
  target. Include what is unresolved and what result would close it. Omit
  this section only when the assessment has no unresolved rows to disclose;
  an unknown or stale observation is not closure. The policy distinguishes
  a disclosed review gap from a blocking prerequisite.
- Evidence query: include an executable revision-based query when the
  provider can resolve it to the original report. Do not emit a placeholder
  query or repeat JJ object identities in the prose.

The implemented input carries =narration.change= and two arrays of
={obligation,text}= rows. Evidence covers supported and contradicted checks;
Scheme labels failed or conflicting outcomes. Open covers every applicable
unresolved commit check. Missing, duplicate and invented narration rows do
not produce a valid preview. =previewDescription= can show an unresolved
draft; =description= is absent when an obligation blocks preparation. The
same preview does not authorize application or transport. For a uniquely
associated PR, ASCENT derives an Open disclosure when a check on the observed
PR head has no completed success or its check inventory is unavailable.
The disclosure is separate from blocking commit prerequisites. The Agent
must explain it in the draft and the ORG review must reference it. The
observation binds the review context across prepare, apply and push.
Provider checks on the PR head do not establish candidate evidence.
Revision query rendering in the commit body remains open.
