* Design finding

The [[file:2026-09-24-retirement-formal-review.org][isolated review model]] prevents observations after its terminal state.
That does not prove that external callers stop sending requests. The new
[[file:../../proof/tla/RetirementIngress.tla][ingress composition]] permits a request before or after retirement, including
a client retaining a cached grant. Merely removing a capability from a graph,
or marking review complete, does not fence these callers.

The modeled correction is ordered: close grant issuance and advance the
authority epoch, drain known work, then finalize. At effect start, recheck the
grant epoch. =EffectAdmission.CurrentGrant= is extracted without changing the
existing =AssuranceLifecycle.StartEffect= predicate; both consumers use that
same operator. This is reuse of a formal authorization contract, not a new
policy evaluator or a claim that Cedar/Runtime already implements the mapping.

The last two are non-vacuity controls, not defects. The safe model includes
explicit terminal self-loops and keeps deadlock checking enabled. Negative
configurations require an actual trace and the named invariant violation, not
an arbitrary nonzero process result.

All 22 configurations across four unittest methods matched their contracts.
The eight existing assurance checks retained exactly their preceding generated
and distinct state counts after extraction of =CurrentGrant=. This is a
regression observation, not a formal equivalence proof of the extraction.
The ingress-only run took 3.407 s and the complete run 14.813 s; these are
single-run wall times including JVM startup, not general performance claims.

Four additional Lean laws prove initial safety, incompatibility of a current
cached epoch with safe retirement, preservation across abstract boundary steps,
and reachable-state safety. They reuse =Retirement.stepPreservesSafety=.
Requests/rejections can stutter after retirement; a current-grant start is not
excluded by a hard-coded retired guard but by the proved fence invariant.
All 20 exported audited laws reported no axioms and no =sorryAx=.

* Explicit abstraction limits

- One pending request and one attempt are modeled, with epochs 0 and 1 and a
  cached epoch 0. Revision, admission, decision and time are fixed to isolate
  revocation. New grant issuance, grant expiry and repeated retries are not
  explored by this composition; the existing lifecycle regression is separate.
- Closing issuance and advancing the epoch is one atomic action. Actual
  distributed ordering, concurrent authorities and restart behavior remain
  obligations, not facts inferred from TLC.
- =known= is an assumption about inventory, not proof of actual completeness.
  Post-retirement discovery of previously unknown work is not covered.
- No fairness or eventual retirement is claimed. Lean's abstract relation is
  not yet a proved refinement of the TLA+ actions or a Scheme implementation.
- Persistence, runtime effects, package publication and remote CI were not
  performed. The worktree remains uncommitted.

These are syntax probes, not standalone resolved modules or TLC checks.
Grammar inspection agrees: only unnamed instance declarations exist, qualified
operator selection has no production, and newlines terminate declarations.
This expands the previous first-failure diagnosis; it does not repair the
parser. No parser-owner source was modified and no downstream fallback added.

Notably the four rejected probes still reported a valid artifact and lossless
roundtrip. Those properties describe a well-formed diagnostic/lossless token
artifact; they do NOT mean successful syntax admission. Qualification must
continue requiring =success AND valid AND exact roundtrip=.

The probe used a bounded =gxi -:max-heap=512M= process with 60-second timeout
and parent source/dependency paths in =GERBIL_LOADPATH=. An initial attempt
omitting the parent source path failed at an unbound observability import;
the corrected path resolved that import without changing dependencies.
