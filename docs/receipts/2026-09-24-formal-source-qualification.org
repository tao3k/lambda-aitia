* What closes here

This follows the [[file:2026-09-24-retirement-ingress-review.org][ingress review]]. The previously rejected multiline and modular
TLA+ forms now parse in the parser owner without changing the Aitia models.
All five maintained models pass syntax success, artifact validity and exact
source-byte roundtrip. TLC and Lean remain independent gates.

The native repair lives in the existing linked gerbil-parser checkout, not a
new Aitia parser. Its grammar now treats newlines as lossless whitespace rather
than declaration terminators. Named instances, qualified names and flat leading
junction expressions have explicit CST nodes. The scope does not include
nested indentation-sensitive junction lists, full TLA+ syntax, configuration
parsing or rebuilt Rust/Rowan AOT products. TLC still performs its own parsing
and semantic checks for the exact models/configurations.

An initial optional-newline production introduced a shift ambiguity at the
next definition and exceeded a 60-second probe. It was replaced, not accepted
as qualified. The stale diagnostic process was interrupted. Gerbil probes
kept a 512 MiB heap; one cold generation diagnostic used a 180-second wall limit.
The final native regression processes completed within the 60-second gate.

* Maintained POO declaration and source binding

[[file:../../user-interface/scenarios/job-retirement-contract.ss][The retirement contract]] declares identity =job-executor/retirement=,
revision =r1=, guarantee =retirement-safety/g1= and four explicit assumptions:
atomic epoch fencing, known inventory, no new grant after closure, and the
single-client bound. It grants no allowed runtime effects.

[[file:../../t/formal/retirement-binding-test.ss][Binding qualification]] uses existing =sdlc-design-implementation-link=,
=sdlc-design-implementation-review=, Assurance snapshots and source digests.
The TLA source group contains four model/helper files and fourteen configs;
the Lean group contains both retirement proof modules. Every member's content
digest participates in its source-group identity. The links bind both groups
to the same contract identity, revision, contract digest and snapshot cut.

Checks confirm that either source-group mutation changes the snapshot context
and invalidates both old links, even if nominal revisions are unchanged. A
changed design assumption also rejects both links as =contract-changed=.
An initial test incorrectly expected =source-changed=; the existing owner
correctly diagnoses =snapshot-changed= first. The test was corrected without
weakening that owner or changing invalidation semantics.

These are declared source bindings. They do not prove that the formal formulas
are faithful projections of the natural-language contract, that a Scheme
implementation refines the models, or that the Host admitted verifier evidence.
Review values continue to report =implementation-conforms?=,
=evidence-admitted?= and =release-authorized?= as false. A source-group manifest
is not a complete verifier/toolchain attestation. The explicit joint gate runs
every verifier; source mapping alone is not evidence-coverage admission.
