* Design question
:PROPERTIES:
:ID: aitia-job-executor-question
:END:

How can one logical job finish after acknowledgement loss without creating a
second external effect? This maintained Aitia work surface connects people,
Agent review roles, design alternatives and bounded evidence in native Org.
Its starting decision is [[file:../../docs/adrs/0008-stable-operation-key-after-lost-ack.org][ADR 0008]], which remains proposed.

This file targets the Scheme-owned Org Elements query path. Its consumer
qualification is pending; legacy CLI queries do not close that gate.
Role references below are proposed
assignments, not registered principals, running Agents or granted capabilities.
The Aitia Org-to-Scheme projection and controlled edit/execution loop remain
pending under [[file:../../docs/rfcs/0005-org-native-engineering-workspace.org][RFC 0005]]. Reading this file executes no source block.

* Organization
:PROPERTIES:
:ID: aitia-job-executor-organization
:END:

Roles refer to the existing POO Flow Organization Bundle concepts. An
application must resolve actual principal/role/Agent identities, visibility
and delegations before scheduling. Org nesting does not confer authority.

| Proposed role | Responsibility | Suggested context projection | Not granted by this document |
|---------------+----------------+------------------------------+------------------------------|
| design-owner | owns requirements, alternatives and ADR proposal | whole design and review findings | self-certification of external guarantees |
| case-reviewer | reviews historical relevance and counterevidence | source inventory, assumptions and alternatives | mutation of provider or release policy |
| guarantee-reviewer | checks gaps across component contracts | requirements, assumptions, owner matrix and scoped receipts | conversion of a hypothesis into proof |
| verification-runner | requests bounded checks through Runtime | selected obligation, bound inputs and tool contract | arbitrary Org code execution or provider credentials |
| decision-reviewer | reviews the proposed choice and its conditions | alternatives, objections, obligations and evidence references | bypassing Cedar / Runtime effect gates |

The same person or Agent may fill more than one role only when the application
permits it; a required independent review must retain actual principal
separation. No Agent is spawned by a heading or an =OWNER_ROLE= property.

* Design decision — stable logical identity
:PROPERTIES:
:ID: aitia-job-executor-design-decision
:STATUS: proposed
:CONTRACT_ORG: lambda-aitia.design-review
:END:

This subtree is the review context for ADR 0008. Its contract checks local
requirements, assumptions, alternatives, review work and receipt references;
passing does not accept the decision or establish any external guarantee.

** Requirements
:PROPERTIES:
:ID: aitia-job-executor-requirements
:END:

*** Unique logical effect
:PROPERTIES:
:ID:         aitia-job-executor-unique-effect
:AITIA_KIND: requirement
:OWNER_ROLE: design-owner
:END:

One logical job operation must not commit a duplicate effect within the
qualified provider contract. Per-key uniqueness is insufficient when a retry
can change its key. A completed review must state the scope rather than claim
unconditional exactly-once delivery.

*** Completion after transient response loss
:PROPERTIES:
:ID:         aitia-job-executor-completion
:AITIA_KIND: requirement
:OWNER_ROLE: design-owner
:END:

The job must be able to complete after transient acknowledgement loss under
explicit service-availability and retry/reconciliation conditions. Turning
off retries cannot silently remove this requirement.

** Assumptions
:PROPERTIES:
:ID: aitia-job-executor-assumptions
:END:

*** Provider retains logical-operation identity
:PROPERTIES:
:ID:         aitia-job-executor-retention
:AITIA_KIND: assumption
:OWNER_ROLE: design-owner
:STATUS:     unqualified
:END:

The provider's deduplication scope and retention cover permitted retries.
There is no measured retention duration in the current fixture. A shortened
retention interval, identity collision or late request reopens this assumption.

*** Effect and deduplication survive failure coherently
:PROPERTIES:
:ID:         aitia-job-executor-atomicity
:AITIA_KIND: assumption
:OWNER_ROLE: guarantee-reviewer
:STATUS:     unqualified
:END:

The actual provider supplies atomic commit or a qualified recovery protocol.
The local SQLite row stands for both the key and the effect; it does not test
an independent external side effect. Two Cedar permits are not a uniqueness
mechanism. A lost ACK leaves the caller uncertain, not entitled to assume no
commit occurred.

** Alternatives
:PROPERTIES:
:ID: aitia-job-executor-alternatives
:END:

#+name: retry-design-alternatives
| Option | Unique logical effect | Completion | Additional obligations | Current judgment |
|--------+-----------------------+------------+------------------------+------------------|
| Stop after lost ACK | avoids a retry-induced duplicate, but does not establish original outcome | not guaranteed | explicit unknown outcome and recovery owner | conflicts with unattended completion unless recovery is added |
| Retry with stable identity | conditional on scope, retention and provider semantics | conditional on availability and retry policy | parameter binding, persistence, concurrent attempts and crash checks | proposed by ADR 0008; one bounded fixture passes |
| Query / reconcile before further action | depends on authoritative correlation and reconciliation semantics | depends on query availability and outcome resolution | bind original identity; absence must not be mistaken for failure when history is incomplete | candidate; no local implementation or receipt |

These are comparisons under the same requirements, not a numeric ranking.
The first and third options are not claimed to have been executed. Reconciliation
may complement stable identity; the alternatives are not inherently exclusive.
