#+title: Contributing to Lambda Aitia

* License

Every contribution is accepted under =Apache-2.0 AND
LGPL-2.1-or-later=.  Source files must carry the repository SPDX header unless
their format is covered by =REUSE.toml=.

* Ownership boundaries

- Lambda Aitia owns Software/SDLC, NASA, GitOps, assurance semantics and its
  Rust runtime and PyO3 bindings.
- Lambda Episteme owns non-SDLC vertical knowledge such as Healthcare.
- Agentic AI Lab owns POO/functional composition, graph substrate and generic
  runtime handoff.  Agentic AI Lab core must never import Lambda Aitia.
- Public extension APIs are ordinary POO-native objects and named pure
  functions.  Raw alist DSLs and anonymous compute hooks are not public APIs.

* Change acceptance

A change is not complete from a happy-path result alone.  It must include the
source owner, negative contracts, focused tests, affected public-consumer tests
and an attributable receipt.  A plan, proof, authorization and executed effect
remain separate facts.

Run the relevant repository gates from the Agentic AI Lab mount:

#+begin_src sh
just build-contribute lambda-aitia
just test-contribute lambda-aitia modules
just test-contribute lambda-aitia assurance
just --working-directory packages/lambda-aitia --justfile packages/lambda-aitia/justfile check-rust-delivery
#+end_src

The AITIA package's =just check= includes the real JJ evidence replay.
From the AITIA package root, =gerbil test dev.ss= runs the Scheme
development suites. =just test-dev= runs the same entry with the
repository's heap limit and timeout.
Set =AITIA_JJ_BIN= to the absolute path of the verified JJ executable
described in [[file:dev/sysml/README.org][the commit evidence qualification]].
The Rust delivery gate requires =AITIA_PYTEST_PYTHON= to name an
absolute interpreter path with the project-pinned pytest installed.
It uses that interpreter for the installed wheel's frozen-source replay.
The Cargo workspace uses optimization level 1 in =dev= and level 3 in
=release=, with incremental compilation enabled in both profiles.

Do not add compatibility aliases, version suffixes to the public Scheme or
Python namespace, or duplicate Aitia semantics in Python.

* Gerbil dependencies and generated products

AITIA declares Lab in =gerbil.pkg=. Lab's package declarations and existing
installer own dependency revisions and installation. CI uses Lab's Just
recipes to build the pinned Core and Lab testing support, then runs AITIA's
Scheme, integration and linked Rust checks.

Keep generated =.ssi=, =.ssxi.ss=, numbered dynamic objects and
=.gxc-complete= files outside Git. Authored =.scm= test fixtures remain source.
A package cache contains build inputs and products. AITIA runs its consumer
checks after cache restoration.

Regenerate the Sources Lock with =dev/standards/update-sources-lock.ss= when
its source inputs change.
